To allow Rancher to work with SELinux, some functionality has to be manually enabled for the SELinux nodes. To help with that, Rancher provides an SELinux RPM.

[TIP]
.Why SELinux?
====
By assigning a dedicated SELinux type to each container, we ensure that containers are limited to their minimal needs and cannot pivot to other resources if compromised.
====

The `rancher-selinux` RPM contains a set of SELinux policies designed to grant the necessary privileges to various Rancher components running on Linux systems with SELinux enabled.

Source code, policy definitions, and development guides are available in the https://github.com/rancher/rancher-selinux[rancher-selinux GitHub repository].

[#_installing_the_rancher_selinux_rpm]
== Installing the rancher-selinux RPM

Install `rancher-selinux` on all SELinux-enabled nodes in the cluster. Replace `<repo-path>` with the corresponding path value from <<tab-supported-os>>.

[#_opensuse_leap_sle_sle_micro_microos]
=== openSUSE Leap, SLE, SLE Micro, and MicroOS

[,bash]
----
cat << EOF > /etc/zypp/repos.d/rancher.repo
[rancher]
name=Rancher
baseurl=https://rpm.rancher.io/rancher/production/<repo-path>/noarch
enabled=1
gpgcheck=1
gpgkey=https://rpm.rancher.io/public.key
EOF

zypper --gpg-auto-import-keys refresh
zypper install -y rancher-selinux
----

On transactional systems such as SLE Micro and openSUSE MicroOS, replace `zypper install` with:

[,bash]
----
transactional-update pkg install rancher-selinux
reboot
----

[#_rhel_centos_rocky_linux]
=== RHEL, CentOS, and Rocky Linux

[,bash]
----
cat << EOF > /etc/yum.repos.d/rancher.repo
[rancher]
name=Rancher
baseurl=https://rpm.rancher.io/rancher/production/<repo-path>/noarch
enabled=1
gpgcheck=1
gpgkey=https://rpm.rancher.io/public.key
EOF

dnf install -y rancher-selinux
----

[#_verifying_the_installation]
=== Verifying the installation

Verify that the Rancher SELinux policy modules are installed:

[,bash]
----
semodule -l | grep rancher
----

[#_configuring_applications_to_work_with_selinux]
== Configuring Applications to Work with SELinux

Installing the `rancher-selinux` RPM on the host does not automatically confine applications. Applications must be explicitly configured to run in an allowed SELinux container domain provided by the RPM.

To configure supported Helm charts to be SELinux aware, set `global.seLinux.enabled` to `true` in the `values.yaml` file when installing or upgrading the chart.

[#tab-selinux-types]
.Dedicated SELinux types by chart
[cols="1,1,1",options="header"]
|===
| Chart | Container | SELinux type
| Rancher Monitoring | node-exporter | `prom_node_exporter_t`
| Rancher Monitoring | pushprox | `rke_kubereader_t`
| Rancher Logging | fluentbit | `rke_logreader_t`
| Rancher AI | rancher-ai-agent | `rancher_aiagent_container_t`
| Rancher AI | rancher-ai-mcp | `rancher_aimcp_container_t`
|===

[NOTE]
====
Only the components listed in <<tab-selinux-types>> receive a dedicated SELinux type. Other Rancher components and general workloads use the default `container_t` domain provided by `container-selinux`.
====
