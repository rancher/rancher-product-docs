Fleet supports deploying application bundles directly from AppCo registries as a native Helm chart source. This integration allows you to leverage AppCo's curated software catalog across all managed Kubernetes clusters using Fleet's GitOps engine.

== Prerequisites

* SUSE Rancher Prime v2.15.0 or later.
* Access to a Fleet GitRepo or Bundle setup in SUSE Rancher Prime.
* Configured credentials or access permissions for the AppCo registry, if using private or enterprise AppCo repositories.

== Deploying an application bundle from AppCo

When creating or editing a Fleet application in the Rancher UI, you can select AppCo directly as your chart repository source.

=== UI workflow

// confirm steps
. In the top-left menu, click *Continuous Delivery* > *Fleet*.
. Select your target *GitRepo* or *Bundle*, or click *Create* to set up a new deployment.
. Under the *Chart Source* configuration section, select *AppCo Registry*.
. Search or select your desired *AppCo Chart* from the drop-down menu and specify the version.
. Configure target clusters, namespaces, and any custom Helm values as needed.
. Click *Save* / *Create*. Fleet will deploy the bundle to the specified downstream clusters.

== Secret management and image pull handling

When deploying AppCo applications to downstream clusters, Fleet automatically handles authentication for container images referenced by the Helm charts.

=== How Fleet manages registry secrets

* *Automatic `imagePullSecrets` generation:* Fleet automatically creates and manages the required `imagePullSecrets` across target namespaces in downstream clusters.
* *Image deployment:* Workload nodes in downstream clusters use these managed secrets to pull Docker images directly from the AppCo registry without requiring manual secret provisioning by administrators.
* *Lifecycle synchronization:* If credentials or registry configurations update, Fleet automatically propagates the changes down to the target cluster secrets.

== Warnings and best practices

[WARNING]
====
*Do not modify AppCo charts directly in Rancher*

Always manage AppCo applications exclusively through your Fleet definitions (GitRepos or Bundles). Direct modifications to Rancher-managed AppCo charts outside of Fleet will *not* be reflected in your Fleet HelmApps. Making manual changes directly in the Rancher UI will cause configuration drift and might prevent Fleet from successfully synchronizing future updates.
====
